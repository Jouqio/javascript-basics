Fetch API

Komunikasi dengan server — GET, POST, PUT, DELETE

Fetch API adalah cara modern browser berkomunikasi dengan server. Kamu kirim request ke URL tertentu, server kirim response balik. Inilah fondasi dari semua web app yang memuat data dari internet.

Pola dasar — selalu dua await

// await pertama: kirim request & tunggu header response const res = await fetch('https://api.example.com/users'); // Selalu cek apakah berhasil (status 200–299) if (!res.ok) throw new Error(`Error ${res.status}`); // await kedua: parse body JSON (ini juga async!) const data = await res.json();

Empat HTTP method — operasi CRUD

GET

Ambil data

Tidak ada body. Paling sering dipakai.

POST

Kirim data baru

Ada body berisi data yang dikirim.

PUT / PATCH

Update data

PUT = ganti semua, PATCH = sebagian.

DELETE

Hapus data

Hapus resource berdasarkan ID.

GET — ambil data

async function getUsers() { try { const res = await fetch('https://api.example.com/users'); if (!res.ok) throw new Error(`Status: ${res.status}`); const users = await res.json(); users.forEach(({ nama, email }) => console.log(`${nama} — ${email}`)); } catch (err) { console.error('Gagal:', err.message); } }

POST — kirim data baru

async function createUser(data) { const res = await fetch('/api/users', { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify(data) // objek JS → string JSON }); if (!res.ok) throw new Error(await res.text()); return res.json(); // server kembalikan data yang dibuat } // PUT/PATCH/DELETE: pola sama, tinggal ganti method

Reusable API helper — pola profesional

async function api(path, { method = 'GET', body } = {}) { const res = await fetch('https://api.example.com' + path, { method, headers: { 'Content-Type': 'application/json' }, body: body ? JSON.stringify(body) : undefined }); if (!res.ok) throw new Error(res.status); return res.json(); } // Satu baris per operasi: const users = await api('/users'); const baru = await api('/users', { method:'POST', body:{nama:'Budi'} }); await api('/users/1', { method:'DELETE' });

Analogi: Fetch = jasa pengiriman paket

Setiap interaksi dengan server seperti transaksi di kantor pos — kamu siapkan paket, kurir antar, gudang proses, lalu balasan datang kembali.

Request = paket yang dikirim

GET = minta kiriman barang dari gudang (tanpa kirim apapun). POST = kamu kirim paket baru. Method menentukan jenis transaksi yang terjadi.

Headers = label dan instruksi di amplop

Content-Type: application/json seperti label "ISI: Dokumen". Authorization: Bearer token seperti kartu identitas pengirim.

Response = tanda terima + isi balasan

Gudang kirim konfirmasi: 200 OK (sukses), 201 Created (dibuat), 404 Not Found, 500 Server Error. Selalu cek res.ok dulu!

Gunakan jsonplaceholder.typicode.com — API gratis untuk latihan, tidak perlu autentikasi.
